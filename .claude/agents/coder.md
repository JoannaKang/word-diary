너는 "말 일기" 프로젝트의 구현 담당자다.

시작하기 전에 반드시 읽어라: `CLAUDE.md`(특히 「데이터 원칙」·「되돌릴 수 없는 것」·「개인정보」),
관련 `docs/design/` 문서, `docs/decision-log.md`.

## 작업 방식

- **TDD 필수**: 실패하는 테스트 → 최소 구현 → 정리. 테스트 없는 동작 코드를 커밋하지 않는다.
- **Apps Script 전역은 어댑터 뒤에.** `SpreadsheetApp`·`DriveApp`·`PropertiesService`를 직접 부르는 코드는
  얇은 어댑터 한 곳에 모으고, 로직은 순수 함수로 빼서 Vitest로 검증한다. 어댑터는 가짜 구현으로 테스트한다.
- 한 번에 한 기능, 파일 2~3개·100줄 이내. 계획에 없는 기능을 얹지 않는다.
- 카테고리 id를 하드코딩하지 않는다. 시트에서 읽은 목록으로 동작한다.
- 테스트 픽스처에 실제 아이 데이터를 쓰지 않는다. 지어낸 예시만.
- 색·크기 하드코딩 금지. 토큰만 사용한다.
- 완료 전 `npm run check`를 돌리고 결과를 있는 그대로 보고한다. 실패도 숨기지 않는다.

## 절대 하지 않는 것

- Drive 파일 삭제·휴지통 이동, 시트 행 삭제, 범위 통째로 덮어쓰기.
- 사진 원본 재인코딩. 원본은 받은 바이트 그대로 저장한다.
- 공유 설정 변경, 외부 서비스 호출.

## 협업 규칙

- 공개 인터페이스·시트 스키마가 계획에 명시돼 있지 않으면 추측하지 말고 질문과 함께 반환한다.
- 자기 워크트리 안에서만 작업하고 거기에 커밋한다. 병합·원격 푸시는 절대 하지 않는다.

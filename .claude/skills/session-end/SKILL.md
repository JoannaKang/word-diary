# 세션 마무리

**매 세션 끝에 같은 것을 요청하지 않으려고 굳혀둔 절차입니다.** 물어보지 말고 아래 순서대로 하세요.

## 0. 무엇이 이번 세션인지부터 정합니다

```bash
git log --oneline -30
git status --short
```

**직전 「인수인계:」 커밋 다음부터가 이번 세션입니다.** 대화 앞부분에 시작 지점이 남아 있으면 그쪽이 더 정확합니다.
작업 나무가 더러우면 **먼저 그것부터 끝내세요.** 정리를 먼저 하면 반쯤 된 작업을 「끝났다」고 적게 됩니다.

## 1. 어디에 적을지 가릅니다

한 곳에 다 적지 마세요. **문서마다 썩는 속도가 달라서** 나눠둔 것입니다.

| 무엇 | 어디 |
| --- | --- |
| 설계에 영향을 주는 결정 (번호) | `docs/decision-log.md` |
| 새로 배운 것, 물었던 함정, 탐사 결과 | `docs/LEARNED.md` |
| 확정된 UX·UI 규칙 | `docs/design/` |
| 아직 안 한 일 + **왜 안 했는지** | `docs/BACKLOG.md` |
| 제품 범위가 바뀐 것 | `docs/PRD.md` (13장 결정 사항 표에도 한 줄) |
| 지금 상태 · 걸려 있는 것 · 다음에 할 일 | `HANDOVER.md` |

**코드가 말하는 것을 문서로 옮기지 마세요.** 산문으로 옮긴 같은 사실은 혼자 남아 틀려집니다.
문서가 답할 것은 **어디를 열지**이지 그 안에 무엇이 있는지가 아닙니다.

**어느 문서에도 실제 아이 데이터(이름·말·사진)나 시트·폴더·스크립트 ID를 적지 마세요.** 저장소가 공개입니다.

## 2. 백로그를 걷어냅니다

이번 세션이 끝낸 항목을 **셋 중 하나로** 처리하세요.

- **순수한 할 일이었다** → 지우고 `HANDOVER.md` 완료 표에 한 줄로 옮깁니다.
- **결정이나 근거가 남아 있다** → 제목에 `✅`, **결론을 맨 위로**. 배경은 아래에 그대로 둡니다.
- **하다가 새로 나온 문제** → **별도 항목으로 빼세요.** 끝난 항목 안에 묻어두면 아무도 안 찾습니다.

사용자가 **명시적으로 미루기로 한 것**은 지우지 말고 `🔒`와 이유를 남기세요.

## 3. 인수인계를 갱신합니다

```bash
wc -l HANDOVER.md                   # 400을 넘기지 마세요
grep -n '아직\|없음\|예정' HANDOVER.md  # 이미 끝난 일을 안 끝났다고 하고 있지 않은지
```

- 1절에 이번 세션을 **한 문단**으로. 지난 세션 문단이 길면 같은 분량만큼 줄입니다.
- **「이번 세션」이라고 쓰지 마세요.** 다음 세션이 읽으면 자기를 가리킵니다.
  세션 글자(A, B, …)를 붙이고, 다음 글자가 무엇인지도 남기세요.
- 테스트 수가 적혀 있으면 갱신합니다.
- 「다음에 열 것」에 **이번에 새로 생긴 것만** 지목합니다. 백로그 전체를 옮기지 마세요.
- 배포(Apps Script 반영)는 **사용자가 했다고 알려준 것만** 「배포됨」으로 적습니다.

## 4. 검증하고 푸시합니다

```bash
git diff --cached --name-only
```

**`.md`만 바뀌었으면 `npm run check`를 건너뜁니다.** 하나라도 아닌 것이 섞였으면 돌리고,
화면이 바뀌었으면 `npm run shot`까지 봅니다. 커밋 메시지는 `인수인계: …`로 시작하는 한국어.
푸시는 지금 작업 중인 브랜치로 `git push -u origin <브랜치>`.

## 5. 끊어도 되는 상태인지 말합니다

셋이 다 맞으면 「여기서 끊어도 됩니다」라고 말하세요. 하나라도 어긋나면 맞춰놓고 말하세요.

1. 푸시가 끝났다
2. 작업 나무가 깨끗하다
3. `HANDOVER.md`가 지금을 가리킨다

# Word Diary — PRD

> 아이가 한 말을 사진과 함께 모아두는 개인용 육아일기 웹앱
> 작성일: 2026-10-12 · 상태: Draft v0.3 (13장 결정 반영)

---

## 1. 배경과 문제

- 만 2세 아이의 말이 빠르게 늘고 있다. 영어와 한국어를 섞어 쓰고, 문장이 길어지고, 감정에 이름을 붙이고, 놀이 규칙을 스스로 만들어 설명하기 시작했다.
- 지금은 문서 한 장(카테고리별 표 5개, 약 25개 항목)에 손으로 정리하고 있다. 이 방식은 다음 문제가 있다.
  - **기록이 느리다**: 말을 들은 그 순간 휴대폰으로 빠르게 적기 어렵다. 표를 찾아가 행을 추가해야 한다.
  - **날짜가 흐려진다**: "날짜 미상", "10월 초", "같은 날" 같은 기록이 많다. 입력 시점에 날짜가 자동으로 잡히지 않아서다.
  - **사진을 붙일 수 없다**: 말이 나온 장면을 함께 남기고 싶다.
  - **데이터가 내 것이 아니다**: 특정 서비스 안에 갇혀 있으면 내보내기·백업·장기 보관이 불안하다.

## 2. 목표 / 비목표

### 목표
1. **들은 즉시 30초 안에 기록**: 휴대폰 홈 화면에서 열고, 말 한 줄 입력하고, 저장.
2. **사진이 있는 육아일기**: 한 기록에 사진 여러 장을 붙이고, 타임라인으로 다시 본다.
3. **데이터 소유권 100% 사용자**: 텍스트는 사용자의 **Google 스프레드시트**, 사진은 사용자의 **Google Drive 폴더**에 저장한다. 앱이 사라져도 시트와 폴더만으로 모든 기록을 읽을 수 있어야 한다.
4. **외부 DB·외부 서버 0개**: Firebase, Supabase, 자체 백엔드 등을 쓰지 않는다.
5. 기존 문서의 기록을 손실 없이 옮겨온다.

### 비목표 (이번 범위 아님)
- 다수 사용자/다수 가정용 SaaS, 회원가입
- 가족 공동 기록 (기록자는 엄마 1명)
- 앱 안에서 포토북·인쇄 레이아웃 만들기 (포토북은 직접 포토프린터로 제작 → 앱은 **갤러리 폴더 정리**까지만 책임)
- 앱스토어 네이티브 앱
- 음성 인식 자동 받아쓰기 (v2 후보)
- 공개 공유·SNS 연동

## 3. 사용자

| 사용자 | 설명 | 핵심 니즈 |
|---|---|---|
| 엄마 (Owner) | 유일한 기록자이자 모든 데이터의 소유자 | 빨리 적기, 사진 붙이기, 다시 보며 즐기기, 데이터 소유, 1년에 한 번 포토북 만들기 |

- 기록 대상 아이는 **여러 명이 될 수 있다**(둘째 대비). MVP는 1명으로 시작하되 데이터 구조는 처음부터 다자녀를 지원한다.
- 가족 열람/공동 기록은 범위 밖. 필요하면 Drive 폴더를 Google 계정으로 직접 공유하면 된다.

## 4. 핵심 사용 시나리오

1. **빠른 기록**: 놀이터에서 아이가 처음 듣는 문장을 말한다 → 홈 화면 아이콘 탭 → 말 입력 → (선택) 상황 한 줄 → 저장. 날짜·시간·당시 나이(예: 2세 7개월)는 자동.
2. **사진과 함께 기록**: 저녁에 오늘 찍은 사진 2장을 골라 낮에 적은 기록에 붙인다.
3. **나중에 보충**: "날짜 미상"인 예전 기록에 대략적 날짜(2026년 10월)를 지정한다.
4. **추억 보기**: 타임라인을 스크롤하며 월별로 본다. "공룡" 태그만 모아 본다. 검색창에 단어를 검색한다.
5. **관심사 변화 보기**: 공룡 → 기차 → … 처럼 시기별로 빠져 있던 것이 태그로 쌓이고, 나중에 관심사 흐름을 돌아본다.
6. **연말 포토북**: 1년에 한 번 Drive의 `gallery/2026/` 폴더를 열면 사진 **원본**이 날짜순으로 정리되어 있다 → 포토프린터로 바로 출력. 사진마다 그날의 말이 정리된 캡션 목록도 함께 있다.
7. **백업/내보내기**: 시트를 그대로 열어 보거나, 앱에서 JSON/CSV 백업을 Drive에 저장한다.

## 5. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = MVP 직후, **P2** = 이후

### 5.1 기록(Entry) 작성 · 편집
| ID | 요구사항 | 우선순위 |
|---|---|---|
| E-1 | 기록 유형: `말`(아이가 한 말), `행동`(말 없이 한 행동 — 예: 선생님께 공룡 이름 알려줌), `에피소드`(노래 바꿔 부르기, 첫 영화 감상 등 서술형) | P0 |
| E-2 | 입력 필드: 아이의 말(필수, 여러 줄 허용, `/`로 변형 표현 묶기 가능), 상황/메모(선택) | P0 |
| E-3 | 날짜 자동 입력(오늘). 날짜 정밀도 선택: `일` / `월` / `시기 미상` — "10월 초", "날짜 미상" 기록을 정직하게 표현 | P0 |
| E-4 | 언어 자동 추정 + 수동 수정: `en` / `ko` / `mixed` | P1 |
| E-1a | 기록 대상 아이 선택(아이가 2명 이상일 때만 선택 UI 노출, 기본값은 마지막에 고른 아이) | P0 (데이터) / P2 (UI) |
| E-5 | 카테고리 1개(기본 5종, 7.3 참고) + 자유 태그 여러 개. 관심사(공룡, 기차 등)는 **태그**로 기록해 시기마다 바뀌는 관심사를 표현 | P0 |
| E-5a | 태그 입력 시 최근 사용 태그 자동완성 | P1 |
| E-6 | 즐겨찾기(⭐) 표시 | P1 |
| E-7 | 편집, 삭제(소프트 삭제 — 시트에서 `deleted_at`만 채움, 휴지통에서 복구) | P0 |
| E-8 | 작성 중 내용 자동 임시저장(네트워크 끊김·앱 전환 대비) | P1 |
| E-9 | "같은 날/같은 놀이" 연결: 기존 기록을 선택해 묶기(`related_entry_id`) | P2 |

## 6. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 기록 속도 | 홈 화면 아이콘 탭 → 저장 완료까지 30초 이내 (텍스트만) |

| 이식성 | 앱 코드 없이도 시트 + Drive 폴더만으로 모든 기록 복원 가능 |
| 비용 | 0원. 단, 원본 보존으로 Drive 용량을 쓴다(사진 1장 3~5MB × 주 10장 ≈ 연 2GB). 무료 15GB는 Gmail·포토와 공유되므로 설정 화면에 사용량 표시 |

|---|---|
| `id` | `k_01`, `k_02` … |
| `name` | 표시 이름(실명). 갤러리 폴더명에도 사용 |
| `birth_date` | `YYYY-MM-DD`, 나이 계산용 |
| `gallery_folder_id` | 아이별 갤러리(원본) 폴더 |
| `web_folder_id`, `audio_folder_id` | 표시용 사본 / 음성 폴더 |
| `order`, `archived` | |

### 7.5 Drive 폴더 구조 — 갤러리
포토북 제작을 위해 **원본은 Drive 폴더만 열어도 바로 쓸 수 있게** 정리한다.
```
Word Diary/
├─ Word Diary (스프레드시트)
├─ <첫째 이름>/
│  ├─ gallery/              ← 원본 사진. 포토프린터 출력은 여기서
│  │  └─ 2026/
│  │     ├─ 2026-10/
│  │     │  ├─ 2026-10-11_143005_01.jpg
│  │     │  └─ 2026-10-11_143005_02.jpg
│  │     ├─ 2026 캡션 (Google 문서) ← D-7 인쇄용 캡션 목록
│     └─ _captions.csv   ← D-7 같은 내용의 표
│  ├─ audio/2026/2026-10/   ← 음성 원본 (P2)
│  └─ .web/2026-10/         ← 앱 표시용 사본 (위치정보 제거, 직접 볼 필요 없음)
├─ <둘째 이름>/ …
└─ backups/
```
- 폴더·파일 날짜 기준: `taken_at`(촬영일) → 없으면 기록 날짜 → 그것도 없으면(`unknown`) 업로드일
- 파일명 `YYYY-MM-DD_HHMMSS_NN.ext`: 이름순 정렬 = 시간순 정렬이라 포토프린터/탐색기에서 바로 순서대로 뽑을 수 있다
- 월 폴더명을 `2026-10`처럼 연도 포함으로 지어 폴더만 따로 복사해도 헷갈리지 않게 한다

### 7.6 `settings` — 설정 (key/value)
`default_child_id`, `root_folder_id`, `backups_folder_id`, `schema_version`

> 민감한 설정(시트 ID 등)은 코드가 아닌 Apps Script **Script Properties**에 저장한다.

## 8. 기존 기록 마이그레이션

- 원본: Claude 문서 "말 모음" 문서 (카테고리별 표 5개, 약 25개 항목 + 표 밖 서술 문단 3개)
- 매핑 규칙
  - 모든 기록 → 첫째의 `child_id`
  - 표 섹션 제목 → `category` ("공룡과 그림 이야기" → `c_interest` + 태그 `공룡`)
  - "아이의 말" 열 → `utterance` / "상황" 열 → `context`
  - 상황에 `YYYY-MM-DD`가 있으면 `date` + `day`
  - "2026년 10월 초", "같은 시기" → `2026-10` + `month`
  - "같은 날", "같은 놀이" → 바로 위 행의 날짜를 상속 (+ P2에서 `related_entry_id` 연결)
  - "날짜 미상" 또는 날짜 정보 없음 → `unknown`
  - 괄호로 된 행동 서술(예: "(선생님께 공룡 이름을 알려줌)") → `type = action`
  - "에피소드" 표 → `type = episode`
  - `/`로 나열된 변형 표현은 한 기록으로 유지
  - 표 밖 서술 문단(좋아하는 공룡, 스스로 만든 놀이 방식 등) → `type = episode`, 날짜 `unknown`
- 방법: 원본을 CSV로 정리 → 시트에 붙여넣기 → 앱의 "ID/나이 채우기" 1회성 스크립트 실행
- 마이그레이션 CSV는 개인 데이터이므로 **저장소에 커밋하지 않는다**.

## 9. 기술 설계 (제안)

### 9.1 후보 비교

| | **A. Google Apps Script 웹앱** (추천) | B. 정적 웹앱 + Google API 직접 호출 |
|---|---|---|
| 구성 | 시트에 연결된 Apps Script가 화면(HTML)과 API를 모두 제공 | GitHub Pages 등에 정적 파일 호스팅, 브라우저에서 OAuth 후 Sheets/Drive API 호출 |
| 서버/DB | 없음 (Google 계정 안에서 실행) | 없음 |
| 설정 난이도 | 낮음 — Google Cloud 프로젝트·OAuth 클라이언트 불필요 | 중간 — Cloud 프로젝트, OAuth 동의 화면, 테스트 사용자 등록 필요 |
| 접근 제어 | 배포 시 "나만" 또는 "특정 Google 계정"으로 제한 | OAuth 토큰(1시간마다 갱신 필요) |
| 데이터 소유 | 코드·데이터 모두 사용자 Google 계정 안 | 데이터는 사용자 계정, 코드는 외부 호스팅 |
| 단점 | 첫 로딩이 다소 느림(1~3초), iframe 안에서 실행되어 PWA·오프라인 제약 | 구현량 많음, 토큰 만료 처리 필요 |

**결정(제안): A안으로 MVP를 만든다.** 데이터 소유권과 설정 단순성이 이 프로젝트의 최우선 가치이기 때문이다. UX 한계(로딩, 오프라인)가 실제로 불편해지면 v2에서 B안 프론트엔드를 같은 시트 스키마 위에 얹는다(데이터 구조는 그대로).

### 9.2 A안 구성
```
[iPhone Safari / 홈 화면 바로가기]
        │  (Google 로그인 세션)
        ▼
[Apps Script 웹앱]  doGet() → HtmlService (UI)
        │  google.script.run (서버 함수 호출)
        ├─► SpreadsheetApp  → Word Diary 시트 (entries / media / categories / children / settings)
        ├─► DocumentApp     → 연간 캡션 Google 문서 (D-7)
        └─► DriveApp        → Word Diary/<아이>/gallery/YYYY/YYYY-MM/*  (원본)
                              Word Diary/<아이>/.web/YYYY-MM/*.jpg  (표시용)
```
- 코드 관리: 이 저장소에서 개발 → `clasp push`로 Apps Script에 배포
- 프론트엔드: 단일 HTML + 바닐라 JS(또는 Preact) + CSS, 빌드 결과를 Apps Script HTML 파일로 인라인
- 사진 업로드: 사진 1장당 서버 호출 2번 — ① 원본 파일 바이트 그대로 → 갤러리 폴더 ② canvas로 리사이즈·EXIF 제거한 사본 → `.web` 폴더. 원본이 실패하면 기록에 "재시도 필요" 표시
- 사진 표시: 서버에서 썸네일 base64 반환 또는 Drive 썸네일 URL (로그인 사용자만 열람 가능)
- 동시성: 쓰기 시 `LockService`로 행 추가 경합 방지
- 조회 성능: 시트 전체를 한 번에 읽어(`getValues`) 클라이언트에서 필터/검색. 기록 수천 개까지 충분

### 9.3 제약/리스크
| 리스크 | 대응 |
|---|---|
| Apps Script 실행 시간 제한(호출당 6분) | 사진은 한 장씩 개별 업로드 |
| 원본 업로드 크기(google.script.run 전달 한도, base64로 약 33% 증가) | M2 시작 전 10MB 사진으로 스파이크 테스트. 한도 초과 시 분할 업로드 후 서버에서 합치기, 그래도 안 되면 원본 업로드만 Drive API resumable upload로 처리 |
| Apps Script 웹앱(iframe)에서 마이크 권한(getUserMedia) 미허용 가능성 | 음성은 P2. A-1(음성 메모 앱 녹음 → 파일 업로드)로 먼저 해결하고, 앱 내 녹음(A-2)은 동작 확인 후 결정. 안 되면 B안 전환 시 함께 해결 |
| Drive 용량 | 설정 화면에 사용량 표시, 화면용 사본은 작게(장당 ~300KB) |
| 일일 쿼터 | 개인 사용량은 한도의 1% 미만 |
| iOS에서 여러 Google 계정 로그인 시 웹앱 접근 오류 | 기본 계정으로 접속 안내, 설정 화면에 계정 표시 |
| 공개 저장소에 개인 데이터 유출 | `.gitignore`에 `*.csv`, `.clasprc.json`, `.clasp.json`(scriptId 포함) 추가, 커밋 전 확인 |

## 10. 화면 구성 (MVP)

1. **타임라인** (홈): 상단 검색/필터, 월별 카드 목록, 우하단 `+` 버튼
2. **빠른 기록** (바텀시트): 말 입력란(자동 포커스) → 카테고리 칩 → 날짜(기본 오늘) → 📷 사진 → 저장
3. **기록 상세/편집**: 사진 갤러리, 모든 필드 편집, 삭제
4. **설정**: 아이 이름·생일(아이 추가), 카테고리, 백업, 갤러리 폴더·시트 바로 열기 링크, 연간 캡션 목록 만들기, Drive 사용량, 휴지통

디자인 톤: 따뜻한 종이 질감의 일기장, 아이의 말은 손글씨 느낌의 큰 인용구, 영어/한국어 모두 잘 보이는 폰트.

## 12. 성공 지표

# 결정 기록 (Decision Log)

설계에 영향을 주는 판단만 번호를 붙여 남깁니다. **되돌린 결정은 지우지 말고 새 항목으로 뒤집습니다.**
제품 범위 결정은 `docs/PRD.md` 13장 표에도 한 줄 남깁니다.

---

## 001. Google Apps Script 웹앱으로 만든다
**날짜** 2026-10-12 · **상태** 확정 (MVP)

시트에 연결된 Apps Script가 화면(HtmlService)과 서버 함수를 함께 제공한다. Google Cloud 프로젝트·
OAuth 클라이언트가 필요 없고, 코드와 데이터가 모두 사용자 Google 계정 안에 있다 — 데이터 소유권(PRD 목표 3·4)에
가장 가깝다. 근거와 비교는 PRD 9.1.

**대가** 첫 로딩 1~3초, iframe 안이라 PWA·오프라인·마이크 권한에 제약. 불편해지면 같은 시트 스키마 위에
정적 웹앱(B안)을 얹는다.

## 002. 시트가 유일한 원본이다
**날짜** 2026-10-12 · **상태** 확정

외부 DB를 쓰지 않는다. 앱은 시트를 읽어 그리고 시트에 쓴다. 시트는 사람이 직접 읽고 고칠 수 있는 모양을
유지한다(PRD D-2·D-3). 앱 없이 시트 + Drive만으로 모든 기록을 복원할 수 있어야 한다.

---

## 003. 사진 원본을 보존하고, 앱에는 사본을 띄운다
**날짜** 2026-10-12 · **상태** 확정

원본은 받은 바이트 그대로 `<아이>/gallery/YYYY/YYYY-MM/`에, 앱 표시용 사본(1600px, EXIF 위치정보 제거)은
`.web/`에 둔다. 갤러리 파일명은 `YYYY-MM-DD_HHMMSS_NN.ext` — 이름순이 곧 시간순이라 포토프린터로 바로 뽑는다.
원본은 앱이 절대 수정·삭제하지 않는다. (PRD 7.5, P-2·P-3)

## 004. 처음부터 여러 아이를 지원하는 구조로 둔다
**날짜** 2026-10-12 · **상태** 확정

MVP는 한 명이지만 `children` 탭과 모든 기록·미디어의 `child_id`, 아이별 Drive 폴더를 처음부터 둔다.
나중에 컬럼을 끼워 넣는 마이그레이션보다 지금 한 칸이 싸다. 아이 선택 UI는 두 명 이상일 때만 나타난다.

## 005. 관심사는 카테고리가 아니라 태그로 표현한다
**날짜** 2026-10-12 · **상태** 확정

「공룡과 그림 이야기」를 `c_interest`(좋아하는 것들)로 넓혔다. 아이의 관심사는 계속 바뀌므로 공룡·기차 같은
구체적 대상은 태그로 남긴다. 카테고리 목록 자체도 시트가 정한다(코드에 하드코딩하지 않음).

## 008. 포토북은 앱 밖에서 — 앱은 정리와 캡션까지
**날짜** 2026-10-12 · **상태** 확정

## 009. 작업 방식은 사용자의 기존 두 프로젝트를 따른다
**날짜** 2026-10-13 · **상태** 확정

`draw-with-me`에서 CTO 오케스트레이션 스킬, ux/ui/coder 에이전트 구성, 번호 붙은 결정 기록, 「요청하지 않은
기능 금지」 규칙을, `london-playtime`에서 작은 커밋·탐사 규칙·스크린샷 픽스처 규칙·왕복 비용 규칙,
`session-end` 스킬, 썩는 속도별 문서 분리(HANDOVER·LEARNED·BACKLOG), 「되돌릴 수 없는 것」 절을 가져왔다.

가져오지 않은 것: i18n 사전(UI는 한국어만, 아이의 말은 데이터라 번역 대상 아님), 백엔드/프론트엔드 에이전트 분리
(서버가 Apps Script 함수 몇 개라 `coder` 하나로 충분), Vercel 프리뷰 배포(배포 대상이 Apps Script — 결정 001).

## 010. 시각 디자인은 A안 「크림 모눈 다이어리」
**날짜** 2026-10-14 · **상태** 확정

사용자가 ui 추천대로 A안을 골랐다. A(크림 모눈)·B(크라프트 줄노트)·C(수채 스크랩북)를 무드보드와 시나리오
전체 목업(A·C 두 벌)으로 비교했다. A는 바탕이 조용해 아이의 말이 먼저 읽히고, 모눈이 목록·입력 화면에서도
일기장 정체성을 지켜 준다. C는 사진이 가장 잘 살지만 수채를 아끼면 화면 대부분이 평범한 흰 앱이 되고,
지켜야 할 대비 규칙이 많았다. B는 갈색 바탕이 사진을 탁하게 했다.

토큰·서체 값은 `docs/design/tone-and-manner.md` A안 절이 원본이다. 아이의 말 손글씨는 Gaegu 700.
`mockups-c.html`은 비교 기록으로만 남기고 이후 화면 작업은 `mockups.html`(A안)을 기준으로 한다.

## 011. 대시보드가 홈, 일기장은 최신순
**날짜** 2026-10-14 · **상태** 확정

사용자는 모은 말을 「대시보드」로 보고 싶어 했고(ux 설계: 일기장을 펼친 첫 장), 기록 순서는 **최근 말이 위**로
정했다. ux는 종이 일기처럼 1일부터 아래로를 추천했지만, 사용자는 가장 최근 것을 먼저 보는 쪽을 골랐다.
날짜 사이도, 하루 안의 말 사이도 최신순이다. 적은 시각은 표시하지 않는다(적은 시각은 말한 시각이 아니다).
주로 폰으로 보므로 넓은 화면 배치는 P2로 내렸다.

## 012. 연달아 한 말은 「이어서 적기」로 따로 기록한다
**날짜** 2026-10-14 · **상태** 확정

ux는 한 기록에 줄을 바꿔 적는 쪽(저장 한 번)을 추천했지만, 사용자는 말마다 사진을 따로 붙이는 경우가 있어
저장 직후 `이어서 적기`로 새 기록을 여는 쪽을 골랐다(PRD E-10). 한 기록은 한 말(과 `/`로 묶은 변형)이 기본이다.
